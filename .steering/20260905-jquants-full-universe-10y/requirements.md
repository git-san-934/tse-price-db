# J-Quants切り替え・全銘柄・長期履歴対応 要求

## 変更・追加する機能
- データ取得元を yfinance(非公式)から J-Quants API(JPX公式)に切り替える。
- 対象銘柄を手動管理の103銘柄から東証の全上場銘柄(約4,000)に拡大する。
- 過去データの取得範囲を1年分から取得可能な最大期間(最大10年超)に拡大する。
- 全銘柄・全期間を一度に取得すると時間がかかるため、銘柄ごとの初回バックフィルと
  完了後の日次差分更新の2段階運用にする。
- フロントエンドが読み込むデータを、全銘柄分をまとめた大きなJSONから、
  一覧用の軽量JSON(`latest.json`)と銘柄クリック時に個別取得する詳細JSON
  (`data/history/<code>.json`)に分割する。

## ユーザーストーリー
- 利用者として、東証の主要銘柄だけでなく全銘柄を対象にしたい。それにより、まだ知らない銘柄も含めて幅広く確認できるから。
- 利用者として、10年程度さかのぼったデータを見たい。それにより、長期的な値動きの傾向も踏まえて判断できるから。
- 利用者として、東証(JPX)公式のデータソースを使いたい。それにより、非公式スクレイピングよりも安定して使い続けられるから。

## 受け入れ条件
- `data/universe.csv` への依存がなくなり、銘柄マスタはJ-Quantsから自動同期される。
- GitHub Actionsのシークレット(`JQUANTS_MAIL` / `JQUANTS_PASSWORD`)を設定すれば動作する。
- 初回実行時、銘柄ごとに取得可能な最大期間のデータが段階的に蓄積される(1回の実行で全て揃わなくてもよい)。
- バックフィル完了後は、日次の軽い差分更新に自動的に切り替わる。
- トップページでバックフィルの進捗(何銘柄完了/全銘柄数)が確認できる。
- 一覧表示時に全銘柄分の詳細履歴を読み込まず、銘柄クリック時にだけ取得する。

## 制約事項
- J-Quantsの無料プランでは直近データに遅延がある場合がある(有料プランで解消可能)。
- J-Quants APIの認証情報はチャットに貼らず、GitHub Actionsのリポジトリシークレットとして設定する。
- 実際のAPIレスポンス形式は開発環境から検証できていないため、初回実行のログを見ながら
  微調整が必要になる可能性がある。
